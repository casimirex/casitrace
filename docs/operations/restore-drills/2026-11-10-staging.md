# Restore drill — 2026-11-10 (staging rehearsal)

- **Result:** PASS
- **Environment:** staging rehearsal of the production stack (`infrastructure/production`, production images and configuration; local S3 and SMTP stand-ins). Run by `restore-drill.sh`.
- **Scenario:** the database disk is lost and one evidence object is deleted. Restore to a point in time chosen before a known later change.
- **RTO (disaster → application serving):** 36 s (target ≤ 4 h). Database restore and WAL replay alone: 14 s.
- **RPO:** WAL is archived at least every 60 s (`archive_timeout`); the last segment before the disaster was archived at 2026-11-10 16:14:30.922767+00. Restoring to `latest` loses at most the unarchived last minute (target ≤ 24 h). This drill restored to an earlier, chosen point to prove point-in-time recovery.
